# Wooden Maze (Unity 3D)

A tilting wooden labyrinth game. A silver marble rolls on a carved wooden board, and you tilt the board
with the arrow keys. Reach **FINISH** to win. Drop into one of the numbered holes and you lose.

Everything is generated by code (board, walls, holes, white route line, hole numbers, wood textures),
so the package has no art assets and works in the Built-in render pipeline and in URP.

## Setup (about 2 minutes)

1. In Unity Hub, create a new **3D** project (Unity 2022.3 LTS or Unity 6, Built-in "3D" or "Universal 3D" template).
2. Copy this whole `WoodenMaze` folder into the project's `Assets` folder, so you get `Assets/WoodenMaze/...`.
3. Wait for Unity to compile, then pick **Wooden Maze > Create Game Scene** from the top menu bar.
4. Press **Play**.

The menu command creates and saves `Assets/WoodenMaze/Scenes/WoodenMaze.unity` (camera, light, game
object, material assets) and adds it to Build Settings.

You can also skip the menu: add an empty GameObject to any scene, add the **Maze Game** component, and press Play.

## Controls

| Key | Action |
| --- | --- |
| Arrow keys (or WASD) | Tilt the maze. Up rolls the marble away from you, Right rolls it right |
| R / Space / Enter | Restart the same maze |
| N | New random maze |
| Esc | Quit (stops Play mode in the editor) |

The timer starts on your first key press. Your best time per maze is saved.

## How it works

| Script | What it does |
| --- | --- |
| `Runtime/MazeGame.cs` | Builds the scene and runs the rules: win at FINISH, lose when the marble drops below the floor through a hole. On-screen HUD. |
| `Runtime/MazeBoard.cs` | The tilting board: a kinematic Rigidbody turned with `MoveRotation`, so the marble's physics react correctly. |
| `Runtime/MazeLayout.cs` | Procedural layout: carves a maze, keeps the longest route, opens extra gaps, places holes next to the route and numbers them in route order. Same seed, same maze. |
| `Runtime/MazeMeshes.cs` | Floor mesh with real round holes cut through it (with a MeshCollider), so the marble falls through physically. |
| `Runtime/MazeTextures.cs` | Procedural walnut wood grain, and the dark floor with the white route line, hole numbers and START / FINISH. |
| `Runtime/MazeMaterials.cs` | Materials for both Built-in (Standard) and URP (Lit). |
| `Runtime/MazeInput.cs` | Keyboard input for both the old Input Manager and the new Input System. |
| `Editor/WoodenMazeSetup.cs` | The **Wooden Maze > Create Game Scene** menu command. |

**The marble** is a Sphere GameObject with a `SphereCollider`, a dynamic `Rigidbody` (gravity, continuous
collision) and a silver material (metallic 1, smoothness 0.92). A realtime reflection probe lets it reflect the board.

**The wood** (walls, frame, box, knobs) and the floor use a matte material: smoothness 0, specular
highlights and reflections off.

## Tuning (select "Wooden Maze Game" in the scene)

- **Seed / Width / Height**: which maze and how big. Default 12 x 10 cells.
- **Hole Density**: share of the cells off the route that become holes (more = harder).
- **Wall Removal**: how open the board is.
- **Max Tilt / Tilt Speed**: how steep and how fast the board tilts.
- **Auto Level**: on, the board eases back to level when you let go. Off, it stays tilted like the real knobs.
- **Gravity Multiplier**: the board is about 40x bigger than a real one, so gravity is boosted (default 3x) to feel right.
- **Hole Radius / Marble Radius**: the hole must be bigger than the marble.

## Notes

- If Unity says the Input System package is missing, either install it (Window > Package Manager) or set
  Player Settings > Active Input Handling to "Input Manager (Old)" or "Both".
- HDRP isn't a target. Use the Built-in or URP templates.
